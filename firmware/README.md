# VibePhone · ESP32-S3「键盘 + 串口」复合设备固件 v2

一个 USB 口（板子上标 **`USB/OTG`** 的那个），同时提供两个功能：

| 接口 | 作用 |
| --- | --- |
| **HID 键盘** | 按键发 **F13 / F14**。拔下来插到任何电脑都还能当普通键盘用，通用性保留 |
| **CDC 串口** | 按键事件的 JSON 消息。电脑端桥接程序读这个口，触发更精确，也便于将来扩展屏幕、麦克风 |

**这个固件本身不依赖任何电脑端软件**——插到任何电脑上，它至少是一个能用的 F13/F14 键盘。

---

## 设备协议（CDC 串口，115200）

按行分隔的 JSON，每条一行、以 `\n` 结尾：

```json
{"t":"hello","ver":1,"btns":2}          上电握手，btns 是按键数量
{"t":"key","btn":1,"ev":"down"}         按键 1 按下（GPIO4）
{"t":"key","btn":1,"ev":"up"}           按键 1 松开
{"t":"key","btn":2,"ev":"down"}         按键 2 按下（GPIO5）
{"t":"ping","up":123}                   心跳，每 3 秒一条，up 是运行秒数
```

> **心跳的用途**：电脑端的监听脚本靠"设备有没有在说话"来确认自己连对了串口。
> 设备刚上电的一两秒里，ESP32-S3 还挂在片内 ROM 的 USB-Serial-JTAG 上，那时也会
> 冒出一个 VID_303A 的串口——连上去能打开、却永远收不到数据。有心跳就能在最多
> 10 秒内判别并自动换到正确的口。`up` 字段还能让电脑端看出设备是不是重启过。

## 二、接线

```
              YD-ESP32-23
        ┌──────────────────┐
        │                  │
        │  GPIO4  ●────────┼──────[按键1]──────┐
        │  GPIO5  ●────────┼──────[按键2]──────┤
        │                  │                  │
        │  GND    ●────────┼──────────────────┘
        │                  │
        └──────────────────┘
```

| 按键 | 一端接 | 另一端接 | 按下时发出 |
| --- | --- | --- | --- |
| 按键 1 | `GPIO4` | `GND` | **F13** |
| 按键 2 | `GPIO5` | `GND` | **F14** |

- 低电平有效（按下 = 接通 GND）
- 四脚轻触开关用**对角**的两个脚，另外两个脚是内部连通的

### ⚠️ 这些引脚千万别接

| 引脚 | 被谁占用 |
| --- | --- |
| `GPIO19` / `GPIO20` | **S3 原生 USB**（D- / D+）——HID 就靠它 |
| `GPIO26` ~ `GPIO32` | 模组内部连 SPI Flash |
| **`GPIO33` ~ `GPIO37`** | **N16R8 的 8MB Octal PSRAM**——最容易被忽略的一处 |
| `GPIO43` / `GPIO44` | UART0（COM 口的日志输出） |
| `GPIO0` / `GPIO3` / `GPIO45` / `GPIO46` | strapping 脚，只能当输入且要小心 |

`GPIO4` / `GPIO5` 不在上面任何一条里，是这块板子上最安全的选择。

## 三、两个 USB 口 —— 其中一个平时必须拔掉

板子上有**两个 USB-C 口**，用途完全不同：

| 口 | 丝印 | 用途 |
| --- | --- | --- |
| USB-串口芯片（FTDI） | **`COM`** | **只在烧录固件时插**。日常必须拔掉 |
| ESP32-S3 原生 USB | **`USB/OTG`** | **功能全在这**：键盘 + 设备协议串口 |

### ⚠️ `COM` 口是一颗"地雷"，日常必须拔掉

**这块板的自动复位电路把 FTDI 的 `DTR` 信号接在了 `GPIO0`（BOOT 选择脚）上。**
后果是：**只要有程序打开 `COM` 口，就会翻转 DTR/RTS，把芯片复位进下载模式**，而且它会**一直卡在那儿**——应用不再运行，键盘和协议串口同时失效，直到你按 `RST` 复位。

会触发的操作包括：

- esptool 烧录
- 任何串口助手 / 串口监视器
- **任何自己写的小工具**（本项目的开发过程中，一个持续读 `COM` 口的日志脚本就反复触发了这个）

**因此：**

| 场景 | `COM` 线 |
| --- | --- |
| **日常使用** | ❌ **拔掉** |
| **烧录固件** | ✅ 插上 → 烧录 → **拔掉** |
| **想看调试日志** | ⚠️ 打开就会复位，**不要用它做实时日志** |

### 出问题时的急救

如果发现**按键突然全部失灵、设备管理器里只有「USB 串行设备」+「USB JTAG/serial debug unit」而没有键盘**——就是这个问题。

**按一下板子上的 `RST` 键即可恢复。**

### 插 `USB/OTG` 口才是正常的

- 插在 `USB/OTG` 口 → ✅ 键盘 + 协议串口都工作
- 插在 `COM` 口（或两个都插着）→ ⚠️ 随时可能把芯片按进下载模式

## 四、编译与烧录

### 用 VS Code（推荐）

1. VS Code 里 `文件 → 打开文件夹`，选择**本目录**（`2.esp32s3usbHID`）
2. PlatformIO 会自动识别 `platformio.ini`，底部状态栏出现一排图标
3. **板子插到 `COM` 口**
4. 点 **✓（Build）** 编译 —— 首次会下载工具链，耐心等
5. 点 **→（Upload）** 烧录

### 用命令行（等效）

在本目录下打开终端：

```sh
pio run                 # 只编译
pio run -t upload       # 编译 + 烧录
pio device monitor      # 看串口日志（Ctrl+C 退出）
```

### 如果烧录失败

ESP32-S3 支持自动进入下载模式，通常不用手动操作。如果一直失败：

1. **按住 BOOT 键不放**
2. **点一下 RST（EN）键**
3. **松开 BOOT 键**
4. 重新点 Upload

## 五、怎么验证它工作了

### 第 1 步：确认复合设备正常枚举

把板子插到 **`USB/OTG` 口**，打开 Windows **设备管理器**：

- ✅ 应该看到一个 **「USB 复合设备」**，下面挂着 **「HID Keyboard Device」**（键盘）和 **「USB 串行设备 (COMx)」**（CDC）
- ❌ 只看到「USB 串行设备」+「USB JTAG/serial debug unit」、**没有键盘** → 应用固件没跑起来，按一下板上的 `RST` 复位

> **重要**：插上电的**头一两秒**，芯片还挂在片内 ROM 的 USB-Serial-JTAG 上，这时看到的
> 「USB 串行设备」是**假的**，打开也收不到任何数据。等两三秒让应用接管 USB 后，
> 才会变成正确的「USB 复合设备」。

### 第 2 步：确认键码正确

浏览器打开任意在线键盘测试页（搜 `keyboard tester`），点一下页面获得焦点，然后按键：

- 按 GPIO4 的键 → 页面应显示 **F13**
- 按 GPIO5 的键 → 页面应显示 **F14**

> 用记事本测是**测不出来**的——F13/F14 在绝大多数软件里没有默认行为，这正是选它们的原因。

### 第 3 步：看调试日志（可选，但强烈建议）

**注意分清楚两个串口**——这是最容易混的地方：

| 串口 | 走哪个 USB 口 | 内容 | 怎么看 |
| --- | --- | --- | --- |
| **`COM` 口**（板载 FTDI） | `COM` | **调试日志**（人看的文字） | `pio device monitor` |
| **`USB 串行设备 (COMx)`**（CDC） | `USB/OTG` | **设备协议**（JSON） | 桥接程序自动读 |

板子**插上 `COM` 口**后执行 `pio device monitor`，应该看到：

```
=========================================
  VibePhone · ESP32-S3 键盘+串口  v2
  按键数：2
    编号1  GPIO4   →  键码 0x68
    编号2  GPIO5   →  键码 0x69
  USB CDC = 设备协议 | UART0 = 本日志
=========================================
[btn] GPIO4  编号1 按下 →  键码 0x68
[btn] GPIO4  编号1 松开 ←  键码 0x68
```

**设备出问题时，这份日志是唯一的窗口**——什么都没有的话，先查是不是插错口了。

## 六、改配置

所有可调项都在 **`include/config.h`**：

| 想改什么 | 改哪个 |
| --- | --- |
| 换按键引脚 | `PIN_BTN_1` / `PIN_BTN_2` |
| 换发出的键码 | `KEY_BTN_1` / `KEY_BTN_2` |
| 开关板载 BOOT 测试键 | 注释/取消注释 `#define ENABLE_TEST_BUTTON` |
| 调整消抖时间 | `DEBOUNCE_MS`（默认 30ms） |
| 调整心跳间隔 | `HEARTBEAT_MS`（默认 3000ms，**别删，见第十一节**） |
| 关掉调试日志 | 注释掉 `#define ENABLE_SERIAL_DEBUG` |

> 按键在**协议里的编号**由 `main.cpp` 的 `g_buttons` 表里的 `number` 字段决定（GPIO4=1、GPIO5=2）。
> 电脑端 `config.json` 的 `device.buttons` 数组按这个编号顺序对应要打开的应用。

常用键码：`0x68`=F13 `0x69`=F14 `0x6A`=F15 `0x28`=Enter `0x29`=Esc `0x2A`=Backspace

## 七、排错

| 现象 | 原因 / 处理 |
| --- | --- |
| **设备管理器里只有串口，没有键盘** | ① 插错口了（要插 `USB/OTG`）；② `platformio.ini` 里的 `ARDUINO_USB_MODE=0` 没生效 |
| **编译报 `USBHIDKeyboard.h: No such file`** | Arduino core 版本太低（需要 3.x）。检查 PlatformIO 是否真的用了 `espressif32@7.1.3` |
| **烧录报找不到串口** | 板子插的是 `USB/OTG` 口，换成 `COM` 口再烧 |
| **按键完全没反应** | 先看串口日志有没有 `[btn]` 输出。有日志但电脑没反应 → 是 USB 模式问题；没日志 → 是接线问题 |
| **开机就进下载模式** | 上电时 BOOT 键（GPIO0）被按住了。松开重新上电 |
| **按一次却触发很多次** | 按键质量差或线太长，把 `DEBOUNCE_MS` 调大到 50 |
| **一打开串口监视器就"自动"发了一次 F13** | 见下方「DTR 与 BOOT 键的相互干扰」，这是硬件设计导致的，不是 bug |
| **串口显示 `SendReport(): not ready`** | **`USB/OTG` 口没插**。原生 USB 上没有主机，HID 发不出去。插上 `USB/OTG` 口即可 |
| **按 F13 却打出了字母 `h`** | `press()` / `release()` 用错了，见下方「press 与 pressRaw 的区别」 |
| **编译报路径相关的奇怪错误** | **工程路径必须全 ASCII**（不能有中文）。这是 ESP32 工具链在 Windows 上的已知问题 |
| **设备管理器里只有「USB 串行设备」+「USB JTAG/serial debug unit」，没有键盘** | **应用固件没在运行**，芯片停在 ROM 的调试接口上。按一下板上 `RST` 复位即可恢复 |
| **刚插上电的一两秒内看到的串口收不到数据** | 那是 ROM 的 USB-Serial-JTAG，不是本固件的 CDC。老式等两三秒；电脑端监听脚本有心跳判断，会自动换到正确的口 |
| **串口能打开但永远没有数据** | 同上——连到 ROM 的调试口了。固件每 3 秒发一条 `{"t":"ping"}`，能用它判断是不是真的连到了设备 |
| **按键突然全部失灵，设备管理器里只有串口、没有键盘** | **芯片被复位进下载模式了**。多半是有程序打开过 `COM` 口（见第三节）。**拔掉 `COM` 线，按一下 `RST` 即可恢复** |
| **电脑端显示「已连接」但按按键毫无反应** | 连到了 ROM 在下载模式下露出的假串口。拔掉 `COM` 线 + 按 `RST`，然后重启电脑端程序 |

## 八、DTR 与 BOOT 键的相互干扰

**这是 ESP32 开发板的通用设计，不是本固件的 bug。**

绝大多数 ESP32 开发板的自动复位电路是这么接的：

```
    USB-串口芯片                ESP32-S3
    RTS ──┬── 三极管网络 ──── EN   (复位)
    DTR ──┴── 三极管网络 ──── GPIO0(BOOT/下载模式)
```

所以 **`DTR` 在硬件上就是连到 GPIO0 的**。每当有程序打开串口（`pio device monitor`、串口助手、甚至某些 IDE 的后台扫描），驱动程序会翻转 DTR/RTS，硬件上等同于**按了一下 BOOT 键**。

而本固件默认把 BOOT 键当成了测试按键 → **于是串口一打开就误发一次 F13**。

### 影响与应对

| 场景 | 影响 | 怎么办 |
| --- | --- | --- |
| 只是调固件、不跑桥接程序 | 无害，F13 本身没有任何默认行为 | 忽略即可 |
| **桥接程序正在运行** | 会误触发打开 Codex/Claude Code | 见下 |
| 已接好实体按键 | BOOT 这个测试键就没用了 | **在 `config.h` 里注释掉 `#define ENABLE_TEST_BUTTON`** |

**接好实体按键后，建议直接关掉 BOOT 测试键**——既避免串口干扰，也让 GPIO0 回归它本来的 strapping 职责。

## 九、press 与 pressRaw 的区别（改键码前必读）

**这是本项目实际踩过的坑。** ESP32 的 `USBHIDKeyboard` 里这两个函数看着像、含义完全不同：

| 函数 | 参数含义 |
| --- | --- |
| `Keyboard.press(k)` | `k < 0x80` 时当作 **ASCII 字符**，查 `_asciimap` 表转换成键码 |
| `Keyboard.pressRaw(k)` | `k` 就是 **原始 USB HID Usage ID**，不做任何转换 |

库里的实现（`USBHIDKeyboard.cpp`）：

```cpp
size_t USBHIDKeyboard::press(uint8_t k) {
    if (k >= 0x88) {         // 非打印键
        k = k - 0x88;
    } else if (k >= 0x80) {  // 修饰键
        _keyReport.modifiers |= (1 << (k - 0x80));
        k = 0;
    } else {                 // ← 打印键：把参数当 ASCII 查表！
        k = _asciimap[k];
        ...
    }
    return pressRaw(k);
}
```

所以 `press(0x68)` 发出的**不是 F13，而是 ASCII `0x68` = `'h'`**——这正是本项目第一版的实际表现：按 BOOT 键，测试页显示 `h`。

**本固件因此统一使用 `pressRaw()` / `releaseRaw()`。** 后续要加按键时，务必沿用：

```cpp
Keyboard.pressRaw(0x68);     // ✅ F13
Keyboard.pressRaw(0x69);     // ✅ F14
Keyboard.pressRaw(0x28);     // ✅ Enter

Keyboard.press(0x68);        // ❌ 发出的是 'h'
Keyboard.press('a');         // ✅ 这个用法才对（ASCII 字符）
```

> 如果哪天想用 `press()`，必须走 `0x88 + 键码` 的形式绕开 ASCII 查表，例如 `press(0x88 + 0x68)`。但可读性差，不推荐。

## 十一、实现要点（改代码前必读）

### 为什么协议发送一定要走 `emitLine()`

`USBHIDKeyboard` 那边有 `press`/`pressRaw` 的坑（见第九节），CDC 这边也有一个**更凶险**的：

core 里 `USBCDC::write()` 的等空间循环**没有超时、没有 yield**：

```cpp
while (to_send) {
    if (!tud_cdc_n_connected(itf)) { size = so_far; break; }
    size_t space = tud_cdc_n_write_available(itf);
    if (!space) { tud_cdc_n_write_flush(itf); continue; }   // ← 死循环
    ...
}
```

`setTxTimeoutMs()` 只管互斥锁，管不到这里。**只要主机"连着"却不读数据，缓冲区一满，整个 `loop()` 就再也回不来**——HID 和 CDC 同时哑掉，而 USB 栈跑在独立任务里，设备管理器看起来一切正常。

所以 `main.cpp` 里所有协议发送都走 `emitLine()`：

```cpp
static void emitLine(const char *line) {
    const int room = Serial.availableForWrite();
    if (room < (int)strlen(line) + 2) return;   // 放不下就丢，绝不阻塞
    Serial.println(line);
}
```

**加新协议消息时务必沿用这个函数，不要直接 `Serial.print`。**

### 心跳不能删

`HEARTBEAT_MS` 定义在 `config.h`。它不只是"保活"——电脑端的监听脚本**靠它判断串口连对了没有**。删掉的话，监听脚本会退化成"取第一个 VID_303A 串口"，在设备刚上电时可能连到 ROM 的假口上，然后一直收不到数据。
