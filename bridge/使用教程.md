# VibePhone 使用教程

> **两种触发方式**：点一下网页控制台再按键盘 `1` / `2`，或者直接按 ESP32 板子上的两个物理按键。
> 前者打开 **Codex 桌面应用**，后者打开**新的终端并运行 Claude Code**。
>
> 本教程所有步骤均已在 Windows 11 + Node v24.14.0 上实机验证通过。

---

## 一、开始前

**程序本身零第三方 npm 依赖**，不用 `npm install`。但需要你的电脑具备下面几项——请逐条确认：

| 条件 | 怎么确认 | 没有怎么办 |
| --- | --- | --- |
| **Windows 10/11** | — | macOS 版代码已附带但**未真机验证**；Linux 不支持 |
| **Node.js ≥ 20** | 命令行执行 `node --version` | 到 <https://nodejs.org/> 装 LTS 版，装完**重开命令行** |
| **Claude Code 已安装并登录** | 新开一个 CMD，敲 `claude` 能正常进入界面 | `npm i -g @anthropic-ai/claude-code`，然后跑一次 `claude` 完成登录 |
| **Codex 桌面应用已安装** | 开始菜单里能找到 **Codex** 或 **ChatGPT** | 不装的话按 `1` 会失败，但按 `2` 仍可用 |
| 默认浏览器可用 | 双击任意网页链接能打开 | — |
| （可选）**ESP32-S3 板子** | 见下方 | **不装也能用**，只是少了物理按键，只能用网页那条路 |

> ⚠️ **最常见的卡点是把 VS Code 里的 Claude 插件当成命令行版。** 两者是独立的：插件装了 ≠ CMD 里能敲 `claude`。**必须在新开的 CMD 里实测 `claude` 能起来。**

### 关于 ESP32 物理按键（可选）

想用物理按键的话，需要：

1. 一块 **ESP32-S3 开发板**（本项目在**优信电子 YD-ESP32-23 V1.3** 上验证）
2. 两个轻触按键，分别接 `GPIO4`—`GND`、`GPIO5`—`GND`（不需要电阻）
3. 板子已经烧好本项目的固件

**固件和接线说明在另一个文件夹**：`..\2.esp32s3usbHID\`（里面有单独的 README）。

**不需要物理按键也完全能用**——把 `config.json` 里的 `device.enabled` 改成 `false`，行为就和只有网页按键时一模一样。

> 本教程的运行环境为 Windows 11 + Node v24.14.0，全部步骤已实机验证通过。

## 二、启动

1. 打开**你解压出来的那个文件夹**（里面能看到 `start-windows.cmd`）
2. **双击 `start-windows.cmd`**

4. 浏览器**自动打开** `http://127.0.0.1:17653/`

## 三、使用

**有两条路可以触发**，互相独立，你按哪个方便就用哪个：

| | 电脑键盘 | ESP32 物理按键 |
| --- | --- | --- |
| 怎么用 | 点一下网页 → 按 `1` / `2` | **直接按，不用点网页** |
| 前提 | 页面获得焦点 | 板子插在 `USB/OTG` 口、桥接程序在跑 |

### 方式 A：电脑键盘（需要点网页）

```text
① 点一下网页（让页面获得焦点）
        ↓
② 按键盘上的 1 或 2
        ↓
③ 应用启动、焦点被抢走 → 想再按，回到 ①
```

**第 ① 步不能省。** 页面底部那行字是实时状态：

- `● 页面已获得焦点，快捷键生效。` —— 绿色，可以按了
- `○ 页面不在前台，快捷键暂停。点击页面恢复。` —— 灰色，先点一下

| 按键 | 效果 | 起始位置 |
| --- | --- | --- |
| **`1`** | 打开 **Codex 桌面应用**。已有窗口时**再开一个新的**，不切回旧窗口 | — |
| **`2`** | 打开**新的 Windows Terminal**，自动运行 `claude` | **你的用户主目录**（`%USERPROFILE%`） |

也可以**直接用鼠标点那两张卡片**，效果相同。

### 方式 B：ESP32 物理按键（推荐，不需要点网页）

板子上接两个按键：

| 按键 | 接在 | 效果 |
| --- | --- | --- |
| **按键 1** | `GPIO4` ↔ `GND` | 打开 **Codex** |
| **按键 2** | `GPIO5` ↔ `GND` | 打开 **Claude Code** |

**直接按就行，任何窗口在前台都生效**，不用先去点网页。

板子要用**标着 `USB/OTG`** 的那个 USB-C 口接到电脑。

### ⚠️ `COM` 口那根线平时必须拔掉

板子上还有一个标着 **`COM`** 的 USB 口。**它是块地雷，日常使用一定要拔掉。**

原因：这块板的自动复位电路把 USB-串口芯片的 `DTR` 信号接在了芯片的 `GPIO0`（BOOT 选择脚）上。**只要有程序打开那个 `COM` 口，芯片就会被复位进下载模式**，然后一直卡在那儿——**键盘和串口同时失效，怎么按都没反应**，直到你按 `RST`。

会触发的包括：烧录工具、任何串口助手、任何自己写的小脚本。

| 场景 | `COM` 线 |
| --- | --- |
| **日常使用** | ❌ **拔掉** |
| **烧录固件** | ✅ 插上 → 烧完 → **拔掉** |

**故障现象**：设备管理器里只剩下「USB 串行设备」和「USB JTAG/serial debug unit」，**没有键盘**。
**解决办法**：拔掉 `COM` 线 → 按 `RST` → 重启桥接程序。

> 两个按键**同时**也会发出 F13 / F14（HID 键盘那条路）。所以你把板子拔下来插到别的电脑，
> 它至少还是一个能用的 F13/F14 键盘——只是那时没有桥接程序，按键不会有任何反应而已。

**开始用之前，板子要插好、桥接程序要启动。** 桥接程序的命令行窗口里出现这几行就说明物理按键就绪了：

```
[serial] 启动，等待设备…
[serial] COM9 收到数据，确认是设备口
```

### 每次按完都要重新点页面（仅方式 A）

按完 `1` 后 Codex 窗口会抢走焦点，页面变成 `○` 状态。**要再按必须先点回网页。**

这是「仅窗口内生效」的必然代价，换来的是：你在浏览器、编辑器里正常打 `1`、`2` 时**不会误触发**。

**方式 B（物理按键）没有这个限制**——随便什么时候按都行。

### 已内置的防误触

- **按住不放只触发一次**（长按去重）
- 两次触发之间至少间隔 **600ms**（`cooldownMs`）
- 启动过程中再按会被拒绝，提示「正在启动，请稍候再按」
- 输入法**正在拼音组合**时按数字键不触发
- 按着 `Ctrl` / `Alt` / `Shift` 时按数字键不触发

### 查看启动记录

页面下方「**启动记录**」列出本次运行的每次触发，含时间和结果：

```text
11:02:31   Codex        已检测到新的 Codex 桌面窗口。
11:03:07   Claude Code  已打开新的 CMD 窗口，并提交 claude 命令。
```

失败会标红并给出具体原因。**失败时不会假装成功**，这是刻意设计——例如未检测到新窗口时会明确报告失败，而不是把「切回旧窗口」记成成功。

### 为什么按 `2` 打开的窗口，和你平时的 CMD 长得不一样？

**这是正常的，不是出错。** 因为它是**另一个终端程序**在渲染，不是 claude 本身不同。

`platform/launch-windows.ps1` 的逻辑是「**有 Windows Terminal 就优先用它**」：

```powershell
$terminal = Get-Command wt.exe -ErrorAction SilentlyContinue
if ($terminal) {          # ← 本机装了 WT，走这条
    wt.exe -w new new-tab --startingDirectory "<你的用户主目录>" cmd.exe /k claude
} else {
    cmd.exe /k claude     # ← 回退：经典 CMD 窗口
}
```

本机的系统默认终端是**经典控制台主机（conhost）**，所以你在开始菜单开的「命令提示符」是经典黑窗；而按 `2` 走的是 Windows Terminal。

| 外观项 | 你平时的 CMD (conhost) | 按 `2` 打开的 (Windows Terminal) |
| --- | --- | --- |
| **窗口框架** | 独立窗口、直角、**无标签栏** | **有标签栏**、圆角、标题栏写 `claude` |
| **字体** | conhost 默认（中文系统常落到新宋体，非美化等宽） | **Cascadia Mono**（等宽、抗锯齿） |
| **配色** | 经典 16 色硬调色板（白字黑底） | **Campbell** 配色 + **24 位真彩色** |
| **渲染引擎** | GDI | DirectWrite |
| **框线 / emoji / 中文对齐** | 容易错位 | 正确对齐 |
| **滚动条** | 传统样式 | 现代细滚动条 |

**这是刻意选择，不是 bug。** Claude Code 的界面靠 24 位真彩色和框线字符绘制，Windows Terminal 渲染更准确；经典 conhost 可能出现颜色失真、框线错位、中文宽度不齐。

**里面的 shell 仍然是 cmd。** Windows Terminal 默认 profile 其实是 PowerShell，但启动器强制传了 `cmd.exe`，起始目录是你的用户主目录（`%USERPROFILE%`），和你平时手动敲 `claude` 的 shell 一致。

#### 顺带一提：存在两个 claude

如果你平时是从 **VS Code 里**开 claude，那连程序都不是同一个：

| 来源 | 版本 |
| --- | --- |
| npm 全局版（在 `cmd` 里敲 `claude` 走的这个） | 2.1.215 |
| VS Code 插件自带版 | 2.1.276 |

在 `cmd` 里敲 `claude` 得到的，与按 `2` 打开的是**同一个二进制**。用 `claude --version` 可确认当前用的是哪个。

> 如果以后想改成经典 CMD 窗口（与平时完全一致），告诉我，可以加一个配置开关，不用手改代码。

## 六、改配置

编辑 `config.json`，**改完先停服务再重启**：

```json
{
  "port": 17653,
  "keys": { "codex": "1", "claude": "2" },
  "cooldownMs": 600,
  "codex": {
    "windowsExecutable": "",
    "windowsStartAppNames": ["Codex", "ChatGPT"],
    "windowsProcessNames": ["ChatGPT", "Codex"],
    "macApp": "Codex",
    "newWindowShortcut": "shift+n"
  },
  "device": {
    "enabled": true,
    "port": "",
    "buttons": ["codex", "claude"]
  }
}
```

| 想改什么 | 改哪个 |
| --- | --- |
| **换个网页触发键** | `keys`，支持数字 `0-9` 或 `F1-F24`，两个键不能相同 |
| **关掉物理按键** | `device.enabled` 改成 `false` |
| **换按键对应哪个应用** | `device.buttons`，按按键编号顺序排。`["claude","codex"]` 就是编号1→Claude Code、编号2→Codex |
| **板子插在固定串口号上** | `device.port` 填 `"COM9"`（**留空更好**，会自动找） |
| **端口被别的程序占了** | `port` 改成别的（如 `17654`） |
| **嫌连按太灵敏 / 太迟钝** | `cooldownMs`，范围 100～10000 毫秒 |
| **自动找不到 Codex** | `windowsExecutable` 填桌面应用 exe 的完整路径（**不要填 CLI**） |
| **Codex 改版后名字变了** | `windowsStartAppNames` / `windowsProcessNames` 加上新名字 |

> **`keys` 和 `device.buttons` 是两套独立的配置**：前者管网页按键，后者管板子上的物理按键。改一个不影响另一个。

## 七、出问题怎么办

看一眼命令行窗口里的 `[serial]` 开头那几行，能定位大部分问题：

| 命令行窗口显示 | 含义 |
| --- | --- |
| `[serial] 启动，等待设备…` | 正在找板子 |
| `[serial] COM9 收到数据，确认是设备口` | ✅ 板子就绪，物理按键可用 |
| `[serial] 按键 1 → codex：...` | ✅ 刚按了物理按键，后面是结果 |
| `[serial] 所有候选口都没有数据` | 板子没插、没烧固件，或固件没在跑 |
| 一直停在「启动，等待设备…」 | 板子没插在 `USB/OTG` 口上 |

| 现象 | 原因 / 处理 |
| --- | --- |
| **电脑键盘按了没反应** | 九成是页面没获得焦点。点一下网页，看到绿字再按 |
| **物理按键突然全部失灵** | ⭐ **最常见的故障**。原因：`COM` 口被某个程序打开过，把芯片复位进了下载模式（见下方「`COM` 线要拔掉」）。**解决：拔掉 `COM` 线，按一下板上的 `RST`** |
| **物理按键按了没反应（首次排查）** | ① 板子插在 `USB/OTG` 口吗（不是 `COM` 口）② 命令行窗口里有没有「收到协议数据，确认是设备口」③ 按一下 `RST` |
| **命令行窗口显示「已连接」但按键没反应** | 连到了假串口（ROM 在下载模式下露出的）。拔掉 `COM` 线 + 按 `RST`，再重启桥接程序 |
| **刚插上板子那一会儿按没反应，过几秒又好了** | 正常。板子上电头一两秒还没接管 USB，程序会自动找到正确的口（最多 10 秒） |
| **页面显示「服务未连接」** | 命令行窗口关了或服务崩了。重新双击 `start-windows.cmd` |
| **提示「端口被占用」** | 已有一个服务在跑（去那个窗口操作），或改 `config.json` 的 `port` |
| **按 `2` 后终端报找不到 claude** | 终端里的 `claude` 没登录或 PATH 有问题。先在普通 CMD 里手动敲 `claude` 确认能起来 |
| **按 `1` 报「未检测到新窗口」** | Codex 版本改版后菜单项名称变了。对照 `platform/launch-windows.ps1` 里匹配的「新建窗口」字样 |
| **`start-windows.cmd` 一闪而过** | 脚本里有 `pause` 会停住显示错误；若没停住，手动在该目录执行 `node bridge.mjs` 看报错 |
| **启动脚本报一堆语法错误** | `.ps1` 的 UTF-8 BOM 丢了，见下方维护须知 |
| **报「在此系统上禁止运行脚本」** | 你的机器有组策略限制。在 PowerShell 里跑一次 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| **按 `2` 打开的窗口和平时不一样** | 正常现象。用的是 Windows Terminal 而非经典 conhost，见第三节末尾的对比表 |
| **只想用网页按键，不想看到串口提示** | 把 `config.json` 里 `device.enabled` 改成 `false` |

## 八、现在的能力边界（重要）

清楚这几条才不会误以为坏了：

| 限制 | 说明 |
| --- | --- |
| **网页那条路必须点一下网页** | 不是全局快捷键。若把 `1`/`2` 做成全局监听，写代码时打个 `1` 就会弹 Codex |
| **物理按键没有这个限制** | 任何时候按都生效，不用点网页 |
| **按 `1` 会不断开出新窗口** | 这是当初选定的行为（再开新窗口，不切回旧窗口）。开多了记得关 |
| **板子必须插在跑桥接程序的那台电脑上** | 物理按键走的是 USB 线，换电脑就不认了。但那时它还是个普通的 F13/F14 键盘 |
| **macOS 版代码已提供，但未真机验证** | 只在本机 Windows 上跑通过。且 `device` 串口触发目前**仅支持 Windows** |
| **不做语音、不做屏幕** | 那是后续步骤的事 |

## 附：维护须知

### `.ps1` 必须保存为带 UTF-8 BOM

`platform/` 下的**每个 `.ps1` 都必须是带 BOM 的 UTF-8**：

- `launch-windows.ps1` —— 负责打开应用
- `serial-windows.ps1` —— 负责读 ESP32 的串口

Windows PowerShell 5.1 执行无 BOM 的脚本时会按系统 ANSI 编码（简体中文下为 GBK）解码，文件里的中文注释随即变成乱码、引号配对错乱。`launch-windows.ps1` 里的 `@'...'@` here-string 会因此打不开、内嵌的 C# 被当成 PowerShell 解析——**该脚本会报 34 处语法错误，启动器完全不工作**。

用编辑器另存时注意别把 BOM 弄丢；`test/bridge.test.mjs` 里有一条断言守着 `launch-windows.ps1` 这一点。

### 两个 `[serial]` 状态行的含义

调试物理按键时，命令行窗口里这两行最有价值：

| 输出 | 含义 |
| --- | --- |
| `[serial] 已连接 COM8 @ 115200` | 打开了串口，但**还没确认**是不是设备 |
| `[serial] COM9 收到数据，确认是设备口` | ✅ **确认了**——收到设备的心跳才算数 |
| `[serial] COM8 10 秒无数据，判定不是设备口` | 连到了假口（设备刚上电时的 ROM 调试口），会自动换下一个 |

**脚本判断"是不是设备"的依据是设备有没有在说话**（固件每 3 秒发一条心跳），而不是猜接口编号——后者在实测中不稳定。

### 为什么「新建窗口」不用快捷键

实测当前商店版（`OpenAI.Codex` 26.915.4065.0）的「文件」菜单为：

| 菜单项 | 快捷键 |
| --- | --- |
| 新建窗口 | **无** |
| 新聊天 | `Ctrl+N` |
| 新建临时聊天 | `Ctrl+Shift+N` |
| 打开文件夹 | `Ctrl+O` |

「新建窗口」**没有分配任何快捷键**，靠 `SendKeys` 永远发不出来；而 `Ctrl+Shift+N` 实际是「新建临时聊天」，它在同一个窗口内开新聊天，不产生新 HWND。

因此改为**通过 UI Automation 直接调用菜单项**，并仍然校验新 HWND：没检测到就报告失败。

> 实现注意：调用必须在**菜单仍展开时**执行。先 `Collapse()` 会让弹出菜单元素失效，`GetCurrentPattern(InvokePattern)` 会抛「不支持的模式」。
